Investigation revealed core architectural incompatibilities between standard Playwright action APIs and the application's underlying SPA framework:React/Vue State Desynchronization: Using Playwright's default .fill() types text into the visual HTML field, but does not trigger the native synthetic onChange or onInput event listeners. The internal application state remains blank, causing submissions to fail even when text is visible.Overlay Interception (tour-step-backdrop): The application uses interactive tour popovers that render invisible backdrop elements. These overlays block Playwright's pointer events during CSS transitions, causing .click() calls to time out indefinitely.DOM Node Recasting: Because the application updates dynamically without full page reloads, locator references frequently become stale across level transitions.Lessons Learned & SolutionsForce State Dispatching: Resolved input desynchronization by explicitly firing synthetic events (locatorInput.dispatchEvent('input')) after populating the selector.DOM-Level Execution Fallback: Bypassed point-interception bugs on the Submit action by evaluating direct click handlers (button.evaluate(b => b.click())) rather than relying purely on standard UI clicks.Sequential Loop Stability: Identified that rigid loop structures in fast automation drivers can easily outpace SPA state renders. Explicit synchronization waits (page.waitForTimeout()) are necessary when dealing with event-heavy UI test sandboxes.
